## AT-18A — real data reaches the normal repository, UI and cache — **PASS**

Ran the app from onboarding through location grant to the nearby screen.

Logcat, filtered to the app's own HTTP tag:

```
09-07 15:37:37.509  D StoryStepHttp: GET api.open-meteo.com/v1/forecast -> 200 (2168ms)
09-07 15:37:43.789  D StoryStepHttp: POST overpass-api.de/api/interpreter -> 200 (8452ms)
```

Two things in that pair are the evidence rather than decoration. The attraction call is a **POST**,
so the coordinates travel in the body and no coordinate appears in the logged request line — the
same NFR-04.3 property the weather path was verified for, obtained here structurally rather than by
redaction. And 8.4 seconds is why this client's timeout is 30 s rather than the default 15 s.

What this shows, point by point:

- **Non-fixture data reaches the normal cache.** 52 fetched records alongside the 5 bundled ones,
  in the same table the nearby list and the detail screen already read.
- **Stable, provider-qualified ids** (`osm:node/…`), which cannot collide with a seed id.
- **The tri-state classification is real, not theoretical.** Five fetched records are `unknown`,
  which under the old boolean column would have been stored as "outdoors" — a claim OSM never made.
  This is REQ-14.3's deferred work, and these five rows are why it was worth doing.
- **Optional fields are preserved**, not discarded: `wikidata` references survive for the
  enrichment follow-up.
- **The area is recorded as fetched**, with its count, so a second query answers from the cache.

Nearby screen (`/tmp/s4.png`): the list shows *University Cenotaph* (public art, 222 m) among the
bundled places, under the line **"Place data © OpenStreetMap contributors, plus bundled sample
places"** — the ODbL attribution, on the screen where the data is displayed, worded from the union
of the sources actually listed.

Detail screen for that fetched record (`/tmp/s6.png`): name, `Public art` and `Outdoor` chips, the
real OSM inscription text as its story, and **"Place data © OpenStreetMap contributors"** below it.
The image is the neutral placeholder rather than a photograph of one of the five bundled landmarks,
which is what the previous fallback would have shown.

No credential exists to expose, and no route or exact position was sent: the request carries the
centre of a 0.01-degree grid cell.

## AT-18B — bad data cannot enter the domain — **PASS**

Covered by `OverpassAttractionSourceTest` (15 cases, `MockWebServer`) and
`RemoteAttractionMapperTest` (28 cases), which together are the FX-HTTP replay:

| Case | Expected | Result |
|---|---|---|
| Valid response | Two validated records with qualified ids | pass |
| `elements: []` | Empty list, **not** a failure | pass |
| Mixed validity | Usable records kept, rest dropped | pass |
| All records invalid | `MALFORMED`, **not** an empty area | pass |
| HTML error page with HTTP 200 | `MALFORMED` | pass |
| Empty body / wrong-shape JSON | `MALFORMED` | pass |
| HTTP 429 | `RATE_LIMITED` | pass |
| HTTP 504 | `RATE_LIMITED` (Overpass's overload signal) | pass |
| HTTP 400 / 500 | `HTTP_ERROR` | pass |
| Dropped connection, unreachable host | `NO_NETWORK` | pass |
| Non-finite and out-of-range coordinates | Record rejected | pass |
| Unnamed record | Record rejected | pass |
| Node + way for one place | Collapsed to the way | pass |
| Two same-named places far apart | Both kept | pass |
| Limit (`out center 60`) | Asserted in the generated query | pass |

`CachedAttractionRepositoryTest` (25 cases) covers the policy above the wire: cache-first, per-area
coalescing, stale fallback, atomic replace, and the empty-versus-broken distinction.

## Offline behaviour — **PASS** (contributes to AT-20A and AT-17B)

With airplane mode on and the app force-stopped, relaunching showed the complete list with **no
HTTP request at all** (`StoryStepHttp` empty for the run). The area was still within its 24-hour
refresh interval, so the correct behaviour is to answer from the cache without trying — which is
what happened.

`aRefreshNeverRemovesTheBundledPlaces` and `refreshingOneAreaDoesNotEmptyAnother` cover the
AT-17B concern in unit tests: a refresh deletes only provider rows, and only inside the box it just
requested, so neither the bundled set nor a neighbouring area is emptied to make room.

## Migration — **PASS**

`StoryStepMigrationTest.migratingToSixMakesTheIndoorClassificationTriStateWithoutLosingRows` builds
a version-5 database with attractions, a saved place, a finished session, a route point and a visit,
runs `MIGRATION_5_6`, and asserts every row survives the three table rebuilds — including that route
points and visits are not taken out by the `sessions` drop-and-rename, and that a recorded
classification becomes `'indoor'`/`'outdoor'` rather than being reset to unknown. `6.json` is
committed and `runMigrationsAndValidate` checks the result against it.
