## What was implemented

Arrival detection and the exactly-once visit that turns it into a story. Before this branch the
`visits` table existed but nothing in `app/src/main` referenced `VisitDao`, and `ArrivalFragment`
was a static prototype reachable only from a debug-only button.

- `domain.arrival` is new and Android-free: `ArrivalPolicy` holds the section 4.5 thresholds as a
  named configuration object, and `ArrivalDetector` decides when a run of fixes is a credible
  arrival.
- `ExplorationCoordinator` owns one detector, resets it on destination change and on each new
  collection span, and records the arrival through the session store. It gates on
  `LocationAccess.PRECISE` and on an actively collecting session.
- `SessionStore` gains `recordVisit`, `findVisit`, `findUnreadVisit` and `markVisitRead`, backed by
  the existing unique `(session_id, attraction_id)` index. **No schema change**: version stays at
  2 and no new migration or schema JSON was produced.
- The arrival prompt is a banner on the exploration dashboard rather than a full-screen page, so a
  live session is not interrupted by an interstitial. `ArrivalFragment`, `fragment_arrival.xml`,
  the debug-only preview button and its `isDebuggableBuild()` guard are all deleted.
- `StoryFragment` gained a ViewModel and now renders the recorded visit's snapshot, falling back to
  the attraction cache, with a fixed source line.

## Contract changes

- `SessionStore` has four new methods (above). `RoomSessionStore` takes a `VisitDao`.
- `ExplorationCoordinator.Observer` has two new default methods, `onPendingStoryChanged(Visit)` and
  `onVisitSaveFailed(boolean)`.
- `ExplorationUiState.from(...)` takes two more arguments.

## The design decision this round turned on

The detector is fed the **raw** fix, before `LocationSampleFilter`. That filter rejects movement
below three metres as receiver noise — which is exactly what a phone standing at the destination
produces. Behind it, the dwell would stop accumulating at the moment the user actually arrives.
`ExplorationCoordinatorArrivalTest.standingStillAtTheDestinationStillArrives` is the regression
that holds this in place, and the emulator run below confirms it against a real location provider.

## Invented content removed

`story_title`, `story_paragraph_one` and `story_paragraph_two` claimed the Old Arts Building was
completed in 1879. The seed dataset says 1924, which is correct. REQ-13.4 forbids unverified
historical claims as fallback content, so those three strings are deleted rather than corrected;
the story now shows the attraction's own description or says plainly that none is available.

## Emulator run (AT-13A A half, AT-13B partly)

Pixel_8 AVD, API 36, `adb emu geo fix` driving position. Sequence: select Old Arts Building from
nearby, start exploring 400 m south of it, approach, then stand still.

```text
approaching 300 m / 150 m / 60 m   banner absent,  visits = 0
standing at 8 m, fixes 5 s apart   banner "You've arrived at Old Arts Building"
                                   visits = 1 row (old-arts, unread=1, name snapshotted)
staying a further 30 s             visits = 1 row       <- no duplicate
rotate to landscape                banner still rendered (same pending state, not re-announced)
tap "Not now"                      banner gone; visit kept, still unread
rotate again                       banner stays gone    <- consumed alert is not replayed
force-stop and relaunch            visits = 1 row       <- recovery inserts nothing
                                   session restored and presented as paused, offering Resume
tap "Read the story"               story screen shows the real 1924 description
                                   plus "Seed dataset · COMP90018 demo"
```

No ANR, no StrictMode violation and no dropped-frame warning attributable to the app appeared in
`logcat --pid`. (An "isn't responding" dialog seen during an earlier attempt was caused by the
test harness polling `uiautomator dump` and copying the database every few seconds on a
software-rendered emulator; it did not recur once the polling was removed, and the app's own pid
logged nothing.)

## Gaps and what is still NOT_RUN

- **AT-12B physical half.** No approach has been walked with a real GNSS receiver. The five
  qualifying approaches and five outside/insufficient-dwell controls per device that D-07 asks for
  have not been done, so the 50 m / 25 m / 3 fixes / 10 s thresholds remain unvalidated against
  real receiver behaviour. Emulated fixes have no drift, no multipath and perfectly reported
  accuracy, so they cannot substitute for this.
- **AT-13B injected-failure half.** The failed-write and retry paths are covered by JVM tests
  only; no storage failure has been injected on a device.
- **AT-13B interrupt-after-commit-before-display.** Covered by force-stopping after the banner
  appeared, which is close but not the same as killing between the transaction committing and the
  UI rendering.
- Only one API level was exercised. API 26 and API 31+ runs, which the checklist requires for
  permission behaviour, have not been done — in particular the approximate-permission refusal path
  has JVM coverage only.
- Story attribution is a fixed string. Real per-record provenance is REQ-18's work; the column
  exists on `attractions` but is not surfaced to the domain model.
