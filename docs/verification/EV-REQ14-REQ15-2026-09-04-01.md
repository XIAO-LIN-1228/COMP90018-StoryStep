## What was implemented

Room is wired into the running application for the first time. Before this branch,
`StoryStepDatabase` was referenced by nothing in `app/src/main` and `AppContainer` assembled
`InMemoryAttractionRepository` and `InMemorySessionStore`.

- Schema export is enabled and `app/schemas/` is committed, with `1.json` captured before the
  schema changed so the migration can be tested from its real starting point.
- Schema version 2 adds `sessions`, `route_points` and `visits`, plus `provenance` and
  `fetched_at_millis` on `attractions`. `StoryStepMigrations.MIGRATION_1_2` is a real migration;
  no destructive fallback is registered anywhere.
- `RoomAttractionRepository` serves the nearby and detail queries from the cache, seeding the
  bundled set once with `INSERT OR IGNORE`.
- `RoomSessionStore` implements the full `SessionStore` contract against the database.
- `ExplorationCoordinator` appends route points incrementally at each checkpoint and adopts an
  unfinished session at launch through `restoreInterruptedSession()`.

## Contract changes

Recorded here because other requirements build on them:

- `SessionStore.findUnfinished` now yields a `RestoredSession` (summary + route + destination
  snapshot) rather than a bare `SessionSummary`. Restoring one of the three without the others
  lets a screen render a session whose distance has not arrived yet.
- `SessionStore` gains `appendRoute(sessionId, firstSequence, points, distance, segmentCount, cb)`
  and `saveDestination(sessionId, destination, cb)`. The caller supplies `firstSequence` because
  only the caller knows which points it has had confirmed; see the defect note below.
- `SessionStateMachine.restore(SessionSummary)` and `RouteAccumulator.restore(points, distance,
  segmentCount)` are new. Both deliberately refuse to carry a live position across the gap.
- `PauseReason.PROCESS_INTERRUPTED` is new.
- `ExplorationCoordinator.Observer.onDurabilityChanged(boolean)` reports a failed checkpoint, and
  the dashboard shows it as an unsaved-progress warning.

## Defects found and fixed during implementation

- **D-P01 duplicated route trace on retry.** The first version of `appendRoute` derived the next
  sequence number from `countBySession`, so a re-offered append wrote the same points again under
  fresh numbers. Caught by `reOfferingPointsThatWereAlreadyStoredDoesNotDuplicateTheTrace`. Fixed
  by having the caller supply `firstSequence`; the unique `(session_id, sequence)` index then
  makes the retry a no-op.
- **D-P02 crash restoring a paused row with no reason.** `SessionSummary` requires a pause reason
  exactly when `PAUSED`, and a row whose state this build cannot read is presented as paused.
  Caught by `anUnreadableStoredStateIsRestoredAsPausedRatherThanCollecting`. Fixed by making the
  pair consistent in `RoomSessionStore.toSummary` rather than letting a launch throw.

## Limitations

- **`connectedAndroidTest` has not been run.** Neither instrumented test has ever executed, so no
  evidence exists that the migration works against real SQLite, that Room's foreign keys cascade
  as assumed, or that the exported `2.json` matches what `MIGRATION_1_2` actually builds. AT-14B
  and AT-15B remain NOT_RUN, and this is the single largest gap on this branch.
- The JVM tests run against fake DAOs on direct executors. They prove the store's rules, not
  SQLite's transaction, rollback or constraint behaviour. `DirectTransactions` provides no
  atomicity at all.
- Process death is simulated by constructing a second coordinator over the same store. That
  exercises the restoration path; it is not a real process kill, and AT-15B's physical half still
  needs a device with the app force-stopped from the recent-tasks list.
- FX-RECOVERY is only partly realised: finished session, unfinished checkpoint, failed write and
  restart-after-interruption are covered by JVM fakes. The duplicate-visit and old-schema-database
  cases exist only in the instrumented tests, which have not run.
- REQ-14.3 is partial. Provenance and fetch time are recorded; the explicit unknown-indoor
  classification named in the plan's section 4.4 is deliberately deferred to REQ-18, because an
  unknown value cannot occur until a real provider supplies one.
- REQ-15.4's "preserve destination snapshots when remote records disappear" is implemented as a
  flattened snapshot on the session row but has not been tested against an actual cache eviction.
- `visits` is created and indexed but nothing writes to it. The table ships now so its migration
  is written and tested once; the arrival detector is REQ-12 and the visit writer is REQ-13.
